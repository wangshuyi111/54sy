## Obsidian + Git 推送：fatal: bad revision 'origin/main'

**问题现象**：用户在 Obsidian 用 Git 插件推送时报 `fatal: bad revision 'origin/main'`，命令 `git rev-parse origin/main` 也会报 "ambiguous argument"。

**根因**（两层叠加）：
1. 本地 main 没有上游分支（`git push -u origin main` 可修复，但仅设置 config，不创建 ref）
2. **仓库是浅克隆**，导致 `git fetch` 即使显示 `* [new branch] main -> origin/main`，也不会真正创建 `refs/remotes/origin/main` 文件 —— 命令"成功"但 ref 不存在

**关键陷阱**：浅克隆下，标准的通配符 fetch refspec `+refs/heads/*:refs/remotes/origin/*` 会失灵。手动 `git update-ref refs/remotes/origin/main <hash>` 也诡异地被静默忽略（即使目录存在也不创建）。任何后续的 `git fetch` 都会清掉手动建的 ref。

**最终修复（持久）**：换成单分支显式 refspec：
```
git remote set-branches origin main
git config remote.origin.fetch "+refs/heads/main:refs/remotes/origin/main"
git fetch origin
```
这样 `git fetch` 会正确创建 `origin/main` 跟踪 ref，且不会被后续 fetch 清掉。

**注意**：
- Obsidian vault 在 `D:/workspace/54sy-blog/content/post`，但 git 仓库根目录在 `D:/workspace/54sy-blog`（向上找）。
- `git push --unshallow` 通过 SSH 会卡住（之前任务卡了 5 分钟后被我 kill）。HTTPS 也连接被重置。所以不要用 unshallow 路径，直接用 refspec 修复。
- 如果进程卡死产生 `shallow.lock`，需用 `taskkill /F /IM ssh.exe /IM git.exe` 后再清理 lock。

**经验**：浅克隆 + 通配符 fetch refspec = 远程跟踪 ref 不存在的隐形 bug。任何 `git rev-parse origin/<branch>` 或 `<branch>@{u}` 都会报错，影响所有依赖这些解析的 GUI 工具（Obsidian Git、VSCode GitLens 等）。
