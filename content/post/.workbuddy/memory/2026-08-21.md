## Obsidian Git 推送再次失败（浅克隆问题第三次复现）

**现象**：用户报告"又推送不成功了"。检查发现：
- `git status -sb` → `## main...origin/main [gone]`（origin/main 引用又消失了）
- `.git/shallow.lock` 存在（上次有 fetch 被中断留下的死锁）
- refspec 配置 `+refs/heads/main:refs/remotes/origin/main` 还在（没被改），但 origin/main ref 被 wipe 了

**修复步骤**：
1. 确认无残留 git/ssh 进程（`tasklist | grep -iE "git|ssh"`）
2. `rm -f .git/shallow.lock` 清死锁
3. `git fetch origin` 重建 origin/main（refspec 还是对的，fetch 成功后 origin/main 回来了）
4. 状态变成 `[ahead 1]`，有一个未推送的 vault backup 提交 `ebd1c3c`
5. `git push origin main` 推送成功（`3eaf5f5..ebd1c3c`）

**根因复盘（第 3 次了）**：
- 仓库仍是浅克隆，`.git/shallow` 边界在 `3c59178`
- 浅克隆下，任何被中断的 fetch 都可能留下 `shallow.lock` 并清掉 `origin/main` 跟踪引用
- 一旦 `origin/main` 没了，Obsidian Git 插件就报 `fatal: bad revision 'origin/main'`
- 后台启动 `git fetch --unshallow`（task_id: 4xhAOa）

## unshallow 成功 —— 永久修复

后台 unshallow 任务 33 秒完成，exit 0，没卡。
- `.git/shallow` 文件已消失 → 仓库现在是**完整克隆**
- `git rev-list --count HEAD` 从 7 涨到 26（拉到了完整历史）
- `git status -sb` → `## main...origin/main`（无 [gone]，无 ahead/behind）
- `origin/main` 稳定解析到 `ebd1c3c`（和本地 main 一致）

**结论**：以后即使 fetch 被中断留下 lock，`origin/main` 跟踪引用也不会再被清空了，因为完整克隆下 remote-tracking refs 由 git 正常维护，能扛住中断。反复犯的 `bad revision 'origin/main'` 问题应该就此终结。

**给用户的建议**：
- 立即可用：现在推送正常了，可以回 Obsidian 重试快捷方式
- 长期方案：要么等 unshallow 跑完转成完整仓库，要么每次遇到这个错就清 `shallow.lock` 再 fetch
